# CLAUDE.md — AI assistant rules for this repository

You are a pair-programmer on a platform engineering project. The human is the architect. Work in **thin vertical slices** that match the phases in `docs/project-plan.md`, never "the whole infrastructure" at once.

Read before working: `docs/project-plan.md`, `docs/architecture.md`, `docs/adr/`, `docs/user-story.md`.

## Project

Deploy the Notes API (FastAPI, multiple replicas) and PostgreSQL with persistent storage on Kubernetes, fully as code. The API is reachable from outside; the database is not. Local-first on `kind`, cloud-ready on AWS EKS with the same charts and platform layer.

## Architecture

- **Three Terraform stacks per environment**, separate state, applied in order (ADR-0002):
  - `10-cluster` — registry + kind cluster (AWS: VPC, EKS, ECR, IAM).
  - `20-platform` — Calico → cert-manager → Envoy Gateway → metrics-server → CNPG operator → observability → (Argo CD). Owns all CRDs.
  - `30-apps` — `notes` namespace, CNPG `Cluster`, Notes API Helm release.
- Reusable modules in `infra/modules/`. `infra/environments/<env>/<stack>/` contains **wiring and `tfvars` only**.
- Own Helm chart in `charts/notes-api/`. Dashboards and alerts in `observability/`. Tests in `tests/`.

## Stack

kind · Terraform (`tehcyx/kind`, `kreuzwerker/docker`, `hashicorp/helm`, `hashicorp/kubernetes`; AWS: `hashicorp/aws` + `terraform-aws-modules`) · Calico · Envoy Gateway (Gateway API) · cert-manager · metrics-server · CloudNativePG · kube-prometheus-stack · Loki · Grafana Alloy · Argo CD (bonus) · GitHub Actions.

Do **not** introduce: ingress-nginx (retired), Bitnami charts/images, Promtail (deprecated), `aws-auth` ConfigMap, DynamoDB state locking.

## Conventions

- **Terraform**
  - Every module has `versions.tf`, `variables.tf`, `outputs.tf`, `main.tf`, and a `README.md` generated by `terraform-docs`.
  - **No provider configuration inside modules** — only `required_providers`.
  - Every variable has `description` and `type`; add `validation` where values are constrained.
  - Use `for_each` over `count` for keyed resources.
  - No hardcoded region, account ID, cluster name or image tag; pass them as variables.
  - Stacks exchange data via outputs and `terraform_remote_state`.
  - Tags/labels come from a shared `tags` / `labels` variable.
- **Versions:** pin Terraform, providers, charts and images exactly. **Never `latest`.** If unsure a version or argument exists, say so — do not guess. Verify against the pinned version's docs: use the `terraform` MCP server (`.mcp.json`) for provider and module docs, and `helm show values <chart> --version <v>` for charts.
- **Custom resources:** a CR whose CRD is installed in the *same* stack goes into a local Helm chart (see `platform-addons/charts/platform-config`), never `kubernetes_manifest`, which fails at plan time before the CRD exists. CRDs themselves may use `kubernetes_manifest`.
- **Readiness:** Helm does not wait for custom resources (e.g. a CNPG `Cluster`). When a later release depends on one being Ready, add an explicit gate (see `notes-app`'s `database_ready`).
- **Images:** builds are reproducible (commit timestamps, no local provenance) and releases pin the registry digest, so re-running `task apps:up` is a no-op.
- **Helm:** `values.schema.json` for every chart; per-environment values files; secrets referenced by name (`existingSecret`), never templated.
- **Images:** built by `task build` / CI, tagged `<git-sha>`. Terraform never builds images.
- **Naming:** lowercase, hyphenated; Kubernetes recommended labels (`app.kubernetes.io/*`).
- **Commits:** Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`, …). Raw AI output and human corrections go in separate commits.

## Hard rules

1. **No secrets** in code, `tfvars`, Helm values or Terraform state. No `random_password` for real credentials. Secrets come from operators (CNPG, cert-manager) or External Secrets (ADR-0007).
2. **Nothing public except the gateway.** The DB is ClusterIP only — never NodePort, LoadBalancer or a route.
3. **Default-deny NetworkPolicies** in `notes`, with only the allows listed in `docs/architecture.md` §3.2.
4. **Pod Security `restricted`** for app workloads: non-root, read-only root FS, drop ALL capabilities, `seccompProfile: RuntimeDefault`, requests/limits, all three probes.
5. **Least-privilege IAM.** No `*` actions or resources without an inline justification. Use Pod Identity and GitHub OIDC; no static keys.
6. **No manual resource creation.** Everything through Terraform, Helm or GitOps.
7. **Never run** `terraform apply`/`destroy`, `helm install`/`upgrade`/`uninstall`, or `kubectl` write commands without explicit human approval.
8. **No AWS credentials in the session.** `.claude/settings.json` blanks the AWS credential env vars and denies access to `~/.aws`. Never try to work around it; AWS stacks are validated offline (`validate`, `tflint`, `trivy`, `infracost`), and AWS applies are run by the human.

## Guardrails (`.claude/settings.json`)

| Tier | Commands |
|---|---|
| **Allowed** | Read-only and validation: `terraform fmt/validate/init/plan/show/output`, `tflint`, `trivy`, `checkov`, `hadolint`, `yamllint`, `kubeconform`, `pre-commit run`, `helm lint/template/show/list/status`, `kubectl get/describe/logs/diff`, `git status/diff/log` |
| **Ask** (human approves each time) | `terraform apply/destroy/import/state rm\|mv`, `helm install/upgrade/uninstall/rollback`, every `kubectl` write (`apply`, `delete`, `patch`, `scale`, `rollout`, `drain`, `exec`, …), `kind create/delete`, `task up/down/build`, `git push` |
| **Denied** | Reading `~/.aws`, `~/.kube/config`, `.env` and `*.tfstate` files; `aws configure/sso/sts`; `eksctl create/delete` |

## Definition of done

A change is done only when:

- [ ] `terraform fmt -check`, `terraform validate`, `tflint`, `trivy config` / `checkov` pass (suppressions justified inline)
- [ ] `helm lint`, `helm template … | kubeconform -strict`, `hadolint`, `yamllint` pass
- [ ] `terraform-docs` and `helm-docs` regenerated
- [ ] Deployed to kind and the relevant `task test` checks pass
- [ ] Re-apply shows no changes
- [ ] No secrets, no `latest`, versions pinned
- [ ] The related story's acceptance criteria are met (`docs/user-story.md`)
- [ ] Prompt log updated in `docs/genai.md`

## How to respond

- In plan mode, list: files to create, resources, inputs/outputs, open questions, **assumptions and uncertainties**.
- After generating, run the validation tools yourself and fix what fails before reporting.
- End every slice with a short list of what you could not verify.
