# Runbook — Notes API platform

> Operational procedures and alert responses. Every alert in `observability/alerts/` must link to a section here. Story: S7.

## Quick reference

| Action | Command |
|---|---|
| Bring everything up | `task up` (add `-- -auto-approve` to skip the three prompts) |
| Run the validation suite | `task test` |
| Tear everything down | `task down` |
| Cluster only | `task cluster:up` / `task cluster:down` (add `-- -auto-approve` to skip the prompt) |
| Verify cluster / verify teardown | `task cluster:check` / `task cluster:check-clean` |
| Platform only | `task platform:up` / `task platform:down` / `task platform:check` |
| Build + push image | `task build` |
| Kube context | `kubectl --context kind-notes-local …` |
| Grafana | `https://grafana.localtest.me` |

## Access

- **Grafana admin password** (generated in-cluster, never in Git):
  `kubectl -n monitoring get secret kube-prometheus-stack-grafana -o jsonpath='{.data.admin-password}' | base64 -d` (user `admin`)
- **DB app credentials** (generated by CNPG):
  `kubectl -n notes get secret notes-db-app -o jsonpath='{.data.password}' | base64 -d`
- **psql into the DB** (from inside the cluster only):
  `kubectl -n notes exec -it notes-db-1 -c postgres -- psql -d app` (local socket inside the pod; no superuser Secret exists)
- **Trust the local CA** (optional, to avoid `curl -k`): export the CA cert from the `cert-manager` namespace and add it to the OS trust store.

## Alerts

Each entry follows the same structure: **meaning → impact → diagnose → mitigate → escalate**.

### NotesApiDown

- **Meaning:** no Notes API target is up, or no ready endpoints behind the Service, for > 2 minutes.
- **Impact:** total outage; availability SLO burning at full rate.
- **Diagnose:**
  1. `kubectl -n notes get pods -l app.kubernetes.io/name=notes-api -o wide`
  2. `kubectl -n notes describe pod <pod>` — look for `ImagePullBackOff`, `CrashLoopBackOff`, failed probes, `OOMKilled`.
  3. `kubectl -n notes logs <pod> --previous`
  4. Check readiness depends on the DB: is the DB up? (see `NotesDbUnavailable` steps).
  5. Check the gateway: `kubectl -n gateway get pods`, `kubectl -n notes get httproute`.
- **Mitigate:**
  - Bad release → `helm -n notes rollback notes-api` (or revert the commit when on Argo CD).
  - Image pull failure → confirm the tag exists in the registry; re-run `task build`.
  - Resource exhaustion → check node capacity: `kubectl top nodes`.
- **Escalate:** if the DB is the cause, follow the DB section.

### NotesApiHigh5xxRate

- **Meaning:** more than 5% of requests return 5xx over 5 minutes (or the SLO fast-burn alert fired).
- **Impact:** partial outage; error budget burning.
- **Diagnose:**
  1. Grafana → Notes API dashboard: which endpoints and which pods?
  2. Loki: `{namespace="notes", app="notes-api"} | json | level="error"`
  3. Did a deploy just happen? `helm -n notes history notes-api`
  4. DB connection errors? Check DB pod status and connection count panel.
- **Mitigate:** roll back the last release; if one pod only, delete it and let the Deployment replace it.
- **Escalate:** if errors persist after rollback, investigate DB and network policies.

### NotesDbPvcUsageHigh

- **Meaning:** a PVC in `notes` is more than 80% full.
- **Impact:** the DB stops accepting writes when the volume is full.
- **Diagnose:**
  1. `kubectl -n notes get pvc`
  2. Dashboard panel: volume usage trend — sudden growth (WAL build-up, failing archiving) or steady growth?
  3. `kubectl -n notes exec <cluster>-1 -- du -sh /var/lib/postgresql/data/pgdata/pg_wal`
- **Mitigate:**
  - Increase `storage.size` in the CNPG `Cluster` values and apply (volume expansion; `gp3` supports it on AWS, `local-path` does **not** — locally, recreate).
  - If WAL is growing because archiving fails (AWS), fix the S3 backup credentials first.
- **Escalate:** plan a capacity review.

### NotesApiCrashLooping (optional)

- **Meaning:** a Notes API container restarted more than 3 times in 15 minutes.
- **Diagnose:** `kubectl -n notes logs <pod> --previous`; look for config errors, missing env vars/Secret, DB auth failures, `OOMKilled` in `describe`.
- **Mitigate:** fix config / roll back; raise memory limit only with evidence from the dashboard.

### NotesApiSloBurn (fast / slow)

- **Meaning:** availability or latency error budget is burning faster than allowed (see [`slo.md`](slo.md)).
- **Diagnose / mitigate:** follow `NotesApiHigh5xxRate` for errors; for latency, check HPA status (`kubectl -n notes get hpa`), CPU throttling and DB query time.

## Operational procedures

### Roll back a release

```bash
helm -n notes history notes-api
helm -n notes rollback notes-api <revision>
```

After Phase 12 (Argo CD), roll back by reverting the commit in Git; a manual `helm rollback` would be reverted by Argo CD.

### Drain a node safely

```bash
kubectl drain <node> --ignore-daemonsets --delete-emptydir-data
# verify the API is still serving
curl -sk https://api.localtest.me/healthz
kubectl uncordon <node>
```

The PDB keeps at least one API replica available. **Locally**, the DB PVC on `local-path` is bound to one node: draining that node makes the DB unavailable until the node is uncordoned.

### Database failover (AWS, 3 instances)

CNPG promotes a replica automatically. To force a switchover:

```bash
kubectl cnpg promote <cluster> <instance> -n notes
```

### Restore from backup (AWS)

Create a new CNPG `Cluster` with `bootstrap.recovery` pointing at the S3 backup (optionally with a PITR target time), verify data, then switch the app's Secret reference. Document every restore test here with date and result.

### Recover from a broken local environment

```bash
task down        # 30 → 20 → 10
task up          # 10 → 20 → 30
task test
```

If `terraform destroy` fails on `10-cluster`, delete the kind cluster and registry containers, then remove the local state files for all three stacks before `task up`.

### AWS teardown verification (Phase 14)

After `task aws:down`, confirm nothing is left billing:

```bash
aws elbv2 describe-load-balancers --query 'LoadBalancers[].LoadBalancerName'
aws ec2 describe-volumes --filters Name=status,Values=available --query 'Volumes[].VolumeId'
aws ec2 describe-network-interfaces --filters Name=status,Values=available --query 'NetworkInterfaces[].NetworkInterfaceId'
aws ec2 describe-nat-gateways --filter Name=state,Values=available --query 'NatGateways[].NatGatewayId'
```

All lists must be empty for resources tagged with this project.
