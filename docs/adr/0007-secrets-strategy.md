# ADR-0007: Secrets strategy

- **Status:** Accepted
- **Date:** 2026-10-11
- **Related:** S4, S5, S8, S10, ADR-0004, ADR-0008

## Context

Terraform stores **all** resource attributes in state in plain text, including Helm release values and any `random_password` result. A secret passed through Terraform is therefore a secret stored in state. We also must not commit secrets to Git.

Secrets in scope: the database credentials, the Grafana admin password, and (on AWS) cloud credentials for CI.

## Decision

**Secrets never pass through Git, `tfvars`, Helm values or Terraform state.**

| Secret | Local | AWS |
|---|---|---|
| DB app credentials | Generated by the **CNPG operator** as a Kubernetes Secret (`<cluster>-app`) | Same, or **External Secrets Operator** syncing from **AWS Secrets Manager** |
| Grafana admin | Generated in-cluster by the chart / an existing Secret | External Secrets + Secrets Manager |
| TLS keys | Generated by cert-manager | cert-manager / ACM |
| CI → AWS | n/a | **GitHub OIDC** → IAM role, no static keys |
| Pod → AWS APIs | n/a | **EKS Pod Identity** (no node-role sharing, no static keys) |

Rules:

- The Notes API chart references secrets by **name** (`existingSecret`) and mounts them as env vars; it never templates secret values.
- No `random_password`, `kubernetes_secret` with literal data, or `sensitive` variable carrying a real secret in Terraform.
- Pre-commit runs secret detection (e.g. `gitleaks`/`detect-secrets`) on every commit.
- The Claude Code session holds no AWS credentials (see [`CLAUDE.md`](../../CLAUDE.md)).

## Alternatives considered

| Option | Pros | Cons | Why not chosen |
|---|---|---|---|
| `random_password` in Terraform | Simple | Secret in plain text in state | Violates the rule |
| Sealed Secrets / SOPS in Git | GitOps friendly | Key management; encrypted secrets still in Git | Unnecessary when operators generate them |
| Vault | Powerful | Heavy to run and operate | Over-engineered for scope |

## Consequences

**Positive**

- State files and the repository contain no credentials; reviewing state is safe.
- The secret contract (Secret name + keys) is the same locally and on AWS.

**Negative / trade-offs**

- Credentials are not visible to Terraform outputs, so tests read them from the cluster (`kubectl get secret`) when needed.
- Rotation on AWS depends on External Secrets refresh intervals.

**Follow-ups**

- Document how to read the DB credentials for debugging in the runbook.
